# Release workflow policy

The release workflow runs only from this shelf's exact current `refs/heads/main` so GitHub can issue a publicly verifiable artifact attestation. A dispatch from any other ref is skipped before credentials are available. The workflow accepts only an explicit signed `FutureDevGuys/homelab` source tag, mints a repository-scoped GitHub App token with read access to that private source, sparsely checks out only `portable/` and the exporter, and receives no homelab decryption key. This shelf has no editable application source, package update, pull-request deployment, mutable mirror, or general automation workflow.

An explicit signed `portable-vX.Y.Z` source tag produces deterministic tar and zip archives, a canonical manifest bound to the exact source tag and commit, `SHA256SUMS`, an SPDX SBOM, and GitHub-signed build provenance. The source-reader App can read only `FutureDevGuys/homelab`; the shelf's ephemeral workflow token creates the draft release. Publication is a manual workflow action that the ordinary contributor App cannot dispatch.

A release version is immutable. The workflow rejects an existing release or tag, builds twice, validates clean archive extractions, creates a draft, downloads every asset for byte equality, and only then publishes it. A failure leaves prior versions unchanged, and a correction uses a higher version. GitHub Releases is the canonical release catalog.
