# Portable release shelf

The public shelf receives only the tagged `portable/` tree and the deterministic exporter from `FutureDevGuys/homelab`. A release uses an exact signed annotated `portable-vX.Y.Z` source tag and source commit. The shelf workflow commit must be the current `main` commit when dispatched and immediately before publication. The ordinary contributor App must not be able to dispatch the workflow.

Before admitting `.github/workflows/publish-portable.yml`, an administrator creates and installs a dedicated GitHub App on only `FutureDevGuys/homelab` with **Contents: read** and no write permissions. Store its App ID as the shelf repository variable `HOMELAB_SOURCE_APP_ID` and its private key as the shelf repository secret `HOMELAB_SOURCE_APP_PRIVATE_KEY`. The release job mints a short-lived token limited to that single source repository and requests only Contents read. GitHub grants Contents read at repository scope, not path scope; the workflow minimizes the material checked out with a partial, sparse checkout of only `portable/` and `scripts/export_portable.py` and does not persist that token in Git configuration. No homelab SOPS identity, git-crypt key, runtime credential or GitHub write token is supplied to the source checkout.

The administrator must use GitHub's supported repository setting to confirm immutable releases are enabled for `FutureDevGuys/compose-apps`, record that readback, and establish a bounded publication window with no other Contents writer able to change the shelf release tag, draft or assets. The workflow's per-version concurrency group prevents two copies of itself from publishing the same version, but does not control other administrators or Apps. Do not merge or dispatch the workflow while hosted Actions remain paused except Renovate.

For the first admitted release, record a new unused `vX.Y.Z` and the exact 40-character source commit, verify the matching `portable-vX.Y.Z` tag is signed and annotated, and dispatch the workflow **from the current shelf `main`** with those two inputs. The workflow compares its exact implementation commit with the current default branch; checks the GitHub-verified signed source tag object and target before and after the build; runs the tagged exporter without any private decryption input; validates the tar, zip, manifest, SBOM and SHA256SUMS as one closed file set; and attests those exact files.

The workflow creates a draft release only after local artifact validation. It downloads every draft asset and compares bytes before publication, then rereads both source and shelf authorities. Publishing requires the administrator's bounded window to remain in effect. After publication it requires the release's native `immutable=true` readback, exact shelf tag target, complete asset set, API SHA-256 digests, downloaded byte equality, and GitHub artifact-attestation verification. Preserve the workflow run and its exact implementation SHA with the release evidence.

If any check fails after the draft or shelf tag is created, leave those objects for investigation and **burn that version**; use a higher version after correction. Do not delete/rewrite a reserved version or claim a draft, matching filename, successful action call or public URL is immutable-release proof.
